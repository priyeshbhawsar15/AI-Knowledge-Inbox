1. Executive summary and scope boundaries

The app accepts a short text note or one public HTTP(S) URL, persists an item and ingestion job, and lets a separate worker fetch/extract/chunk/embed it. Ready chunks and Float32 vectors are durable in SQLite. The Express API maintains a disposable exact-cosine index, embeds questions, retrieves top chunks, and asks an OpenAI-compatible chat model for a schema-validated answer using only labeled source context.

Web

React 19 + Vite

Hooks, typed API client, clear polling/answer/source states.

Runtime

Express + TypeScript

One API process and one durable ingestion worker.

Storage

SQLite WAL

Items, jobs, chunks, Float32 vectors, events, index version.

In scope

  • Plain-text notes and one-page public URL ingestion.
  • Durable asynchronous fetch, extraction, token-aware chunking, embedding, list/status, retrieval, cited answers.
  • Structured logs, typed validation/errors, retries, lease recovery, health checks, local Docker Compose.

Out of scope

Auth/accounts/sharing, edit/delete, file upload, crawling, browser rendering, OCR, streaming answers, Kubernetes, Redis, dedicated vector DB, and horizontal scaling. Private trusted use only, ≤10,000 items, best-effort availability.

Confirmed stack

Node.js 22 LTS, strict TypeScript, Express, React 19/Vite, better-sqlite3, Drizzle ORM/migrations, Zod shared contracts, official OpenAI JS client with configurable base URL, Vitest/Supertest/RTL/Playwright. Production Express serves the built SPA.

Defaults

Page size 25/max 100; newest first; worker polls 500 ms; three transient attempts (2 s/8 s/32 s + jitter); note max 50,000 chars; question max 2,000; request max 256 KiB; content retained for database life; UTC storage and browser-local display.

Frontend visual and interaction direction

Primary job

Give one private operator near-zero-friction capture and immediately scannable notes. A compact “Take a note or paste a URL…” composer expands in place to title, text/URL mode, Save, and Cancel. A pending card appears only after durable 202.

Viewing model

Content-led masonry-like grid: four columns wide, two tablet, one mobile. Cards show title, bounded preview or hostname, browser-local time, and ingestion state. Open a centered desktop dialog or full-height mobile sheet; long content scrolls inside while list position is preserved.

Original visual identity

Google Keep inspiration is behavioral, not a clone: warm paper-neutral canvas, charcoal text, white/soft-tint cards, one golden accent, subtle elevation, 12–16 px radii, and system type. No Google logos, exact palette, proprietary icons, or pixel-matched geometry. A slim “knowledge pulse” edge communicates queued, processing, ready, or failed with text/icon support.

Controls and accessibility

/ focuses search, n focuses the composer outside text fields, and Escape cancels/closes. Hover actions remain keyboard visible. Require semantic dialog focus trap/return, AA contrast, 44 px mobile targets, reduced motion, no color-only status, and no horizontal overflow at 390 px. Review 1440×1000, 768×1024, and 390×844.

Scope guard: pinning, labels, archive, checklist notes, drag reordering, and per-note colors are not implied by the inspiration and remain out of scope unless approved separately.

4. Core flows, consistency, and idempotency

Ingestion

Validate + normalize→TX: item + queued job + event→202 + status URL→Atomic worker claim→Fetch if URL→Extract/chunk/embed→TX: chunks + ready + index version

Creation is one transaction. Final chunks, embeddings, item ready, job succeeded, version increment, and completion event are another. All generation is staged in memory, so partial chunks are never visible.

Idempotency: optional UUID-like Idempotency-Key (≤128 chars) maps to SHA-256 request hash and original item/job for 24 h. Same key/body replays the original 202; same key/different body is 409 IDEMPOTENCY_CONFLICT. Without a key, every request creates an item; hashes do not silently deduplicate intent.

Query

Validate question→Refresh complete index if stale→Embed question→Exact cosine top-K→Load source metadata→Grounded structured chat→Validate citation IDs

Only ready chunks matching configured embedding model/dimension are eligible. Sources are untrusted quoted context, not instructions. No score above MIN_RELEVANCE_SCORE returns an explicit insufficient-context answer without a chat call.

5. API and event contracts

JSON, unknown fields rejected. Bodies ≤256 KiB; note ≤50,000 chars; question ≤2,000; URL ≤2,048. Assignment endpoint names remain unprefixed; breaking changes use /v2, additive fields may extend v1.

POST /ingest

{"type":"text","content":"A note...","title":"Optional"}
{"type":"url","url":"https://example.com/article"}

Optional Idempotency-Key. Returns 202:

{"item":{"id":"itm_...","type":"url","status":"queued","createdAt":"..."},"jobId":"job_...","statusUrl":"/items/itm_..."}

Errors: 400 validation, 409 idempotency conflict, 413 too large, 429 queue full/rate limit, 503 database busy.

GET /items and GET /items/:id

Cursor pagination by (created_at DESC,id DESC), optional status, page 25/max 100. Summaries expose title/type/source URL/status/timestamps/safe error; detail adds chunk count. Raw content and vectors never appear. Missing detail is 404.

POST /query

Request: {"question":"What did I save about rate limiting?","topK":5}
Response: {"answer":"The note recommends backoff [S1].","sources":[{"citationId":"S1","itemId":"itm_...","title":"Retry notes","url":null,"snippet":"...backoff...","score":0.82}],"requestId":"req_..."}

Errors: 400 validation, 409 index model mismatch, 422 no ready content, 502 provider/invalid response, 503 index unavailable.

Health and errors

GET /health/live is process liveness. GET /health/ready checks current migrations, writable DB, compatible vector metadata/index; worker heartbeat appears as a check. Error envelope:

{"error":{"code":"URL_PRIVATE_ADDRESS","message":"The URL does not resolve to a public address.","details":{},"requestId":"req_..."}}

Persisted internal events

ingest.accepted, started, retry_scheduled, succeeded, failed, index.reloaded, query.completed. Events store IDs/type/time and safe JSON metadata only; they are not an external event bus.

UUIDv7 IDs have readable prefixes. Embeddings are normalized little-endian Float32; byte length must equal dimensions × 4. 7. Stateful behavior and transition rules

Item/job lifecycle

queued→processing/running→ready/succeeded
processing→retry_wait→processing→failed (terminal)
TransitionGuard/triggerEffectsRetry/recovery/invalid
new → queuedValidated request and idempotency guard.Item/job/event one TX.3 lock retries; conflict is 409; otherwise no mutation.
queued/retry → processingAtomic eligible claim; no valid lease.Lease, attempt++, item state, event.60 s lease, 15 s heartbeat; zero-row claim is ignored.
processing → readyAt least one chunk, all vectors compatible.Replace chunks, clear error, succeed job, version++, event one TX.Lock retry; invalid transition is rejected/logged.
processing → retryTransient and attempts remain.Clear lease, available time, safe error/event.2/8/32 s + jitter; rejects terminal/exhausted.
processing → failedPermanent or exhausted.Clear lease, safe code/message, event.Terminal; manual requeue out of scope.

Startup and 30-second reaper reclaim expired running jobs into retry wait; attempts are not decremented. One job at a time. Generation is replay-safe because only the final transaction replaces chunks.

Vector index

uninitialized → loading → ready → reloading → ready; incompatible/malformed data → degraded. Reload off-side and atomic swap preserve the old complete snapshot. No durable index state besides DB version/model metadata.

Query

Request-scoped validated → embedded → retrieved → generated → returned, terminal insufficient-context/failed. It is not queued or audited with content. Client disconnect aborts provider calls where possible; JSON is buffered, so no retry after response begins.

8. Security, privacy, permissions, and abuse controls

  • No auth by confirmed scope: bind locally/private only; public exposure requires auth and user ownership before launch.
  • SSRF: HTTP(S) only; reject credentials, default-disallowed ports, localhost, and loopback/private/link-local/multicast/reserved IPs. Resolve/revalidate every connection and redirect (max five), defend rebinding, no proxy.
  • Bounded fetch: 30 s total, 10 s connect/header budget, 2 MiB streamed body, HTML/plain text only, one page, identifiable user-agent.
  • Prompt injection: source content is untrusted quoted data; tool calls disabled; schema output and citation allowlist; source HTML never rendered.
  • Secrets/privacy: key via environment/.env, never browser/log/repo. Chunks and questions go to the configured provider; UI/README disclose this and promise no sensitive-data classification.
  • Web controls: remove scripts/styles/forms; React text rendering; CSP, nosniff, no-referrer.
  • Abuse: 10 ingest/min and 30 query/min per IP in memory, queue max 1,000, bounded body/topK/context. Adequate only for one API process.
  • Audit: request/job IDs and safe events; no provider payloads, embeddings, prompts, note/page text, secrets, or URL query strings in logs.

Runbooks

  • Stuck job: inspect item, heartbeat, events; restart only after confirming lease expiry; never hand-mark ready.
  • Index mismatch: compare config to system state; revert or explicit reindex; do not edit metadata.
  • Backup/restore: stop writers or use online backup; dated copy; restore to new volume; integrity check, migrations, readiness, known query.
  • Queue pressure: return 429 at 1,000, keep queries alive, fix provider/network, then drain with one worker.

10. Deployment, scalability, observability, cost, and targets

Compose

api: same app image, serves API/SPA on container 3000, host default 127.0.0.1:3000, shared knowledge-data:/data. worker: same image with worker command and volume, no port. Multi-stage build, non-root. Development uses npm workspaces and runs Vite/API/worker separately; Gaming PC preflight found Node 22/npm 12 available and Corepack/pnpm absent.

Configuration

DATABASE_PATH, AI_BASE_URL, AI_API_KEY, EMBEDDING_MODEL, EMBEDDING_DIMENSIONS, CHAT_MODEL, score/log/fetch/retry limits. Startup validates and logs non-secret names/values.

Observability

Pino JSON fields: service/version/environment, request/job/item IDs, route/event, duration, attempt, status/error. Log metrics for ingest outcomes/stages, queue, query/provider latency and tokens, retrieval counts/scores, index count/version/reload, DB retries, heartbeat. Never log source text/prompts/vectors/keys/full query URLs.

Engineering targets, not guarantees

  • Ingest acceptance p95 <500 ms; item list p95 <200 ms locally.
  • Query p95 <15 s normal provider latency; local retrieval <500 ms at ≤10k items.
  • Idle worker starts job within 2 s; expired job recovered within 90 s.
  • Best effort; daily local backup RPO 24 h, recovery target 1 h.

What breaks and production evolution

Search is O(chunks × dimensions); SQLite has one writer; index and rate limits are process-local; queue is one-consumer. At scale use PostgreSQL, pgvector/managed ANN, Redis/SQS, object storage, multiple stateless APIs/workers, distributed limits, auth/tenant ownership, managed secrets/backups, tracing/metrics, and residency controls—preserving domain/HTTP contracts behind adapters.

Cost controls

Batch embeddings, chunk hashes avoid retry re-embedding, cap document/chunks/context/topK, use a small configurable chat model, record token counts only, and skip chat on insufficient retrieval.

11. Test plan, acceptance, rollout, and implementation sequence

Test plan

  1. Unit: contracts, SSRF/redirect/rebinding matrix, extraction/chunks, vectors/cosine, lifecycle guards, error/prompt/citation validation.
  2. Persistence/integration: migrations, constraints, atomic creation, idempotency, claim/lease recovery, final publish, WAL retries, index version/model mismatch.
  3. API: every status/schema/body limit, pagination, raw-content exclusion, readiness, no-content/provider errors.
  4. Worker: fixture redirects/private/timeout/oversize/types, fake-AI batch/dimension failures, crash before final commit.
  5. Frontend: collapsed-to-expanded composer; text/URL mode; validation, save/cancel, and retained input after error; responsive masonry-like card grid; desktop dialog/mobile sheet focus trap and return; pending/failed knowledge-pulse states; browser-local timestamps; /, n, and Escape behavior; citations; reduced motion, live regions, long-note overflow, and 1440×1000, 768×1024, and 390×844 viewport checks.
  6. E2E: Compose + fake AI/fixture page; ingest note+URL, ready, query/citations, restart and prove persistence/index rebuild; optional non-sensitive real-provider smoke.
  7. Security/quality: audit/secret scan, ESLint/strict TS/build, CSP, safe text rendering, SSRF matrix.

Acceptance criteria

  • All assignment UI flows and exact endpoint names work.
  • Note typing and viewing are recognizably inspired by Google Keep's low-friction composer and card-based scanning while retaining original branding, palette, icons, and geometry; desktop, tablet, and mobile meet the documented interaction and accessibility invariants.
  • Accepted jobs survive worker restart; no partial chunks searchable.
  • Items reach ready or stable clear failure; query citations are allowlisted and include title/URL/snippet/score; insufficient context is honest.
  • Full Compose restart preserves state and rebuilds index.
  • Every redirect/private address and fetch limit is tested.
  • Structured correlated logs contain no source/prompts/vectors/secrets.
  • All tests pass and README covers setup, chunk/vector rationale, limits, production evolution, and provider disclosure.

Rollout/rollback

  1. Fake AI + fixture URL; migrate and pass readiness/E2E.
  2. Real key locally; two non-sensitive samples and query.
  3. Restart both containers; repeat list/query.
  4. Rollback image; schema rollback only with tested down migration or pre-migration backup—never older code on incompatible DB.

Implementation sequence

  1. Monorepo/tooling/contracts/config/logger/Compose.
  2. Schema/migrations/repositories/lifecycle tests.
  3. Ingest/items/queue/lease recovery.
  4. Safe fetch/extract/chunk fixtures.
  5. Embedding gateway/final publish/vector index.
  6. Query/prompt/citation contract.
  7. React/accessibility.
  8. Health/rate limits/logging/backups/E2E/security/README.
